# 演示用例

## 用例 1：知识库检索

### 输入
```
帮我查一下知识库里关于微服务架构的内容
```

### 预期输出
系统经过 6 步检索流水线后返回：

> 根据知识库中的内容，微服务架构是一种将应用程序拆分为多个小型、独立部署服务的架构风格。
>
> **核心设计原则**（根据片段 1、3）：
> - 单一职责：每个微服务只负责一个业务领域
> - 服务自治：独立部署、独立数据库、可独立选择技术栈
> - 去中心化数据管理
>
> **容错设计**（根据片段 1）：
> - 断路器模式（Circuit Breaker）：如 Sentinel、Hystrix
> - 重试机制：指数退避 + 最大重试次数
> - 降级策略：核心功能降级，非核心功能关闭
>
> 如需了解更多细节，可以进一步询问具体的设计模式。

### 验证点
- ✅ Supervisor → general → ReAct 工作流
- ✅ Agent 调用 search_knowledge 工具
- ✅ 检索结果经过完整 RAG 管道
- ✅ Token 记录写入 ai_token_usage

## 用例 5：邮件发送流程

### 输入（第一轮）
```
帮我把本周的备忘录用邮件发给我自己
```

### 预期输出（第一轮）
```
正在获取本周备忘录...

本周（2026-07-27 ~ 2026-08-02）共有 2 条备忘录：
1. 团队周会（7月28日）
2. 紧急修复数据库连接池泄漏（7月27日）

即将发送邮件，请确认：
- 收件人：[您的邮箱]
- 主题：本周备忘录汇总
- 内容：2 条备忘录

确认发送吗？
```

### 输入（第二轮）
```
确认
```

### 预期输出（第二轮）
```
已发送到您的邮箱
```

### 验证点
- ✅ Agent 先查日期 → 查备忘录 → 查邮箱 → 展示确认 → 等待用户回复
- ✅ 邮件内容中不泄露邮箱地址
- ✅ send_formatted_email 正确调用
